# `meticulous try`

Self-serve trial: a developer with only a Meticulous login runs `meticulous try` in their repo,
and their local Claude Code builds the app, records sessions of it and backtests Meticulous
against recently merged PRs, then reports what Meticulous would have caught. No GitHub
integration, CI changes or commits.

## Flow (`start.command.ts`, the default subcommand)

1. `start/resolve-try-app.ts` — reuses onboard's app discovery/picker; a non-interactive
   monorepo run leaves the choice to the agent instead of failing.
2. `start/self-onboard-project.ts` — OAuth login (`intent=onboard`, always OAuth, never
   `METICULOUS_API_TOKEN`), then `POST oauth/self-onboard` via `selfOnboard` in
   `@alwaysmeticulous/client`. Idempotent per (user, repo name); also sets the OAuth default
   project. Error kinds (rate limited, project cap, …) map to `CliUserError`s.
3. `start/materialize-try-workspace.ts` — writes the gitignored `.meticulous-try/` workspace:
   the vendored `templates/` (CLAUDE.md, `agents/`, `skills/`), a generated
   `.claude/settings.json` (`start/try-settings.ts`: allowlist incl. the detected package
   manager, denylist for git writes) and `.mcp.json` (onboard's `mergeJsonMcp`). Writes go
   through onboard's `safe-repo-fs` (no symlink escapes).
4. `shared/try-context.ts` — `try-context.json`, mode 0600 (holds the project API token).
5. `start/launch-try-agent.ts` — launches Claude Code through onboard's `launchOnboardTool`
   with `METICULOUS_API_TOKEN` in its env, so every `meticulous …` command the agent and its
   subagents run is scoped to the trial project. `--printOnly` prints a launch command that
   reads the token from the context file instead of printing it.

## The agent's playbook (`templates/`)

Copied into `dist/` by `scripts/copy-try-templates.mjs` and versioned with the CLI.
`CLAUDE.md` defines four phases, each with a skill: build & serve (saves a recipe), record
coverage (crawler + `session-recorder` subagents over CDP), backtest PRs (one `pr-backtester`
subagent per PR, launched in parallel), report.

Apps behind a login go through the `try-app-login` skill before recording: the agent looks for a
dev auth bypass first, then picks a mechanism by where the app keeps its session — browser login
captured by `meticulous try login` (cookies / local storage; also covers SSO and MFA), test
credentials typed into each recording (session storage / IndexedDB), or a token — and pauses once
for the user. Only recording needs the login: replays restore the recorded state.
